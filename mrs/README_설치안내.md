# MRS 설치 안내 (PHP 웹호스팅용)

PMS 파트관리시스템과 같은 웹호스팅(PHP + MariaDB)에 올려 `https://www.datanex.io.kr/mrs` 로 접속하는 버전입니다.
Python·composer 가 필요 없고, FTP 로 올린 뒤 설치 화면에서 DB 정보만 입력하면 됩니다.

## 1. 서버 요구 사항
- PHP 7.4 이상 (8.x 권장)
- 확장: `pdo_mysql`, `mbstring`, `zip`(PPT·엑셀 생성), `openssl`(암호화·메일 보안 연결), `curl`(Claude AI 호출, 없으면 규칙 기반 초안만 사용)
- MariaDB 10.x / MySQL 5.7 이상 (PMS 와 같은 DB `datanex8` 사용)
- 대용량 로그를 올리려면 `upload_max_filesize`, `post_max_size` 를 50M 이상으로 늘려 주세요.

## 2. 올리기
1. 이 `mrs` 폴더 전체를 FTP 로 `www/mrs/` 에 올립니다.
2. 폴더 권한은 755, 파일 권한은 644 로 둡니다. 707·777 처럼 다른 사용자에게 쓰기를 열면 호스팅에 따라 "Internal Server Error"가 날 수 있습니다. 설치 시 `config.php` 와 `data/` 폴더를 자동으로 만듭니다.

## 3. 설치
1. 브라우저에서 `https://www.datanex.io.kr/mrs/install.php` 를 엽니다.
2. 서버 환경 점검이 모두 "정상"인지 확인합니다.
3. DB 정보(호스트·포트·DB 이름 `datanex8`·사용자 `datanex8`·비밀번호)와 최초 관리자 계정을 입력하고 **설치 시작**을 누릅니다.
   - 기존 `pms_` 테이블은 건드리지 않고 `mrs_` 로 시작하는 테이블 15개만 추가합니다. (참고용 DDL: `database.sql`)
4. 설치가 끝나면 **서버에서 `install.php` 를 삭제**합니다.

## 4. 처음 설정 ([시스템 설정] 화면, 관리자만)
- **회사 정보**: 회사명, 주소. 보고서의 연락처·이메일은 각 보고서 **담당 엔지니어의 사용자 정보**에서 가져옵니다.
- **메일 발송**: 발송 방식을 고릅니다.
  - **일반 SMTP**: 서버, 포트, 보안 연결(STARTTLS/SSL/없음), 계정, 비밀번호.
  - **Microsoft 365 (OAuth)**: 회사 M365에 "보안 기본값"이 켜져 SMTP 로그인이 막힐 때(`535 5.7.139`) 씁니다. 보안 정책은 그대로 두고 Graph API로 보냅니다. 아래 **4-1** 의 Azure 앱 등록이 필요합니다.
  - 어느 방식이든 [저장] 후 [테스트 메일 보내기]로 확인합니다.
- **Claude AI**: Anthropic API 키. Claude Console(platform.claude.com) → API Keys 에서 발급하며, 사용한 만큼 과금됩니다.
- **기존 고객 DB 연동**: 기본 `pms_customers`. [고객] 화면에서 PMS 고객을 불러오면 담당자1·2가 전산담당자로 함께 들어옵니다. (읽기 전용)
- SMTP 비밀번호, M365 클라이언트 암호, API 키는 `config.php` 의 secret 으로 암호화해 `mrs_setting` 테이블에 저장합니다.

## 4-1. Microsoft 365 메일 발송 준비 (Azure 앱 등록, 처음 한 번)
M365 **전역 관리자** 계정으로 진행합니다. 약 10분 걸립니다.

1. https://portal.azure.com 접속 → 위쪽 검색창에 **Microsoft Entra ID** 입력 → 들어가기.
2. 왼쪽 **앱 등록** → **+ 새 등록**.
   - 이름: `MRS 메일 발송` (아무 이름이나 가능)
   - 지원되는 계정 유형: **이 조직 디렉터리의 계정만**
   - 리디렉션 URI: 비워 둠 → **등록**
3. 만들어진 앱의 **개요** 화면에서 두 값을 메모장에 복사합니다.
   - **애플리케이션(클라이언트) ID**
   - **디렉터리(테넌트) ID**
4. 왼쪽 **인증서 및 비밀** → **+ 새 클라이언트 암호** → 설명 `MRS`, 만료 **24개월** → 추가.
   - 표에 나온 **값**을 바로 복사합니다. (화면을 벗어나면 다시 볼 수 없습니다. "비밀 ID"가 아니라 **값**입니다.)
   - 만료일을 달력에 적어 두세요. 만료되면 새 암호를 만들어 MRS에 다시 넣어야 합니다.
5. 왼쪽 **API 사용 권한** → **+ 권한 추가** → **Microsoft Graph** → **애플리케이션 권한** → 검색창에 `Mail.Send` → 체크 → **권한 추가**.
   - 이어서 **"(회사명)에 대한 관리자 동의 허용"** 버튼 → 예. 상태가 초록색 **허용됨**이 되어야 합니다.
6. (권장) 이 앱이 **보고서 발송용 메일함 하나로만** 보내도록 제한합니다. 그대로 두면 회사의 모든 메일함 이름으로 보낼 수 있는 권한입니다.
   Exchange Online PowerShell 에서:
   ```powershell
   Connect-ExchangeOnline
   New-DistributionGroup -Name "MRS 발송 허용" -Type Security -Members report@회사도메인
   New-ApplicationAccessPolicy -AppId <클라이언트 ID> -PolicyScopeGroupId "MRS 발송 허용" -AccessRight RestrictAccess -Description "MRS는 report 메일함만"
   ```
7. MRS [시스템 설정] → **발송 방식: Microsoft 365** → 테넌트 ID, 클라이언트 ID, 클라이언트 암호(값) 입력.
   **보내는 사람 주소**에는 실제 메일함 주소(예: `report@회사도메인`, Exchange 라이선스 필요)를 넣고 [저장] → [테스트 메일 보내기].

자주 나는 오류
- `AADSTS7000215` 클라이언트 암호가 틀림 → **값**을 다시 복사해 넣기
- `AADSTS7000222` 암호 만료 → 4번을 다시 해서 새 암호 입력
- `403 ErrorAccessDenied` → 5번의 관리자 동의가 안 됐거나, 6번 정책의 허용 그룹에 보내는 주소가 없음
- `404 / ErrorInvalidUser` → 보내는 사람 주소가 실제 메일함이 아님
- 첨부 합계 약 2.8MB 초과 시 이 방식으로는 보낼 수 없습니다. (보고서는 보통 100KB 안팎)

## 5. 사용자 · 권한
[사용자 · 권한] 화면에서 엔지니어를 등록합니다. 이메일·연락처를 꼭 입력하세요. 보고서 표지·서명란·메일 서명에 그대로 쓰입니다.
역할(관리자/매니저/엔지니어/조회자) 기본 권한에 더해, 사용자별로 권한을 켜고 끌 수 있습니다.

### 5-1. 팀 (팀장 · 팀원)
- 사용자 목록의 팀 칸은 없앴습니다(사용자는 **부서**로 구분합니다). 이미 지정해 둔 팀장·팀원 관계는 그대로 남아 아래 기능에 쓰입니다.
- 팀장은 팀원의 고객 정/부 담당을 바꾸고 담당을 이관할 수 있으며, 대시보드 **[우리 팀]** 탭과 **우리 팀 현황** 표에서 팀원별 담당 고객·진행 중 보고서·위험 보고서를 봅니다.
- 관리자는 대시보드에서 전체 담당자 현황을 봅니다. 보고서 목록·위험 판정 보고서에는 **담당** 엔지니어가 표시됩니다.

### 5-1-0. 정 / 부 사이트
- 고객 목록과 보고서 생성 1단계 위쪽의 **[정 (내가 정 담당)] / [부 (그 외 모든 사이트)]** 버튼으로 볼 사이트를 고릅니다.
- 내가 정(주 담당)이 아닌 사이트는 따로 지정하지 않아도 모두 **부**로 자동 처리됩니다. 고객당 정은 1명이며, [정 담당하기]로 바꿀 수 있습니다.
- 로그 보관함·오프라인 수집함의 고객 목록도 [정] 사이트가 먼저, 나머지는 [부]로 표시됩니다.

### 5-1-1. 부서
- 관리자는 [사용자 · 권한] 아래 **부서 설정** 표에서 부서를 추가·이름 변경·삭제합니다. 부서를 지우면 소속 사용자는 '부서 없음'이 됩니다.
- 사용자 목록의 **부서** 칸(또는 사용자 수정 창)에서 부서를 배정합니다. 위쪽 부서 필터로 부서별 사용자만 볼 수 있습니다.
- 대시보드 **장비 판정 현황**의 [부서별] 탭은 고객 정 담당자의 부서 기준으로 집계합니다.

### 5-1-2. 비밀번호 변경 주기 (3개월)
- 로그인한 지 3개월(90일)마다 비밀번호 변경 안내 창이 뜹니다. [지금 변경] 또는 [3개월 뒤에 다시 알림]을 고를 수 있습니다.
- 비밀번호를 바꾸면 그날부터 다시 3개월이 계산됩니다. 임시 비밀번호로 로그인한 경우에는 연기할 수 없습니다.

### 5-1-4. 목록 기간 (최근 3개월)
- 보고서 관리, 장비·로그 보관함(로그·성능 아카이브), 대시보드, 감사 로그, 보관 로그 목록은 기본으로 **최근 3개월** 자료만 보입니다. 보고서는 점검일 기준이며, 아직 끝나지 않은(작성 중·검토 중) 보고서는 날짜와 상관없이 보입니다.
- 이전 자료는 지우지 않고 그대로 보관합니다. 목록 위 기간 칸에서 **최근 6개월 / 최근 1년 / 전체 기간 / 기간 지정 (지난 자료 조회)** 을 고르면 볼 수 있습니다.

### 5-1-3. 대시보드
- 고객 · 관리 장비 · 보관 로그 · 전체 보고서 숫자를 누르면 해당 목록이 열립니다.
- **장비 판정 현황**: 장비별 가장 최근 로그 기준 위험/요주의/정상/로그 없음 막대와 담당자별·부서별 표. 줄을 누르면 해당 장비 목록이 뜹니다.
- **위험 · 요주의 장비** 표에서 줄을 누르면 그 고객의 장비·로그 보관함으로 갑니다.

## 5-2. 로그 · 성능 아카이브 넣기
- 로그는 **장비별로** 넣습니다. [장비 · 로그 보관함] 또는 보고서 생성 3단계에서 **해당 장비 칸**에 끌어다 놓으세요. (장비 없이 한꺼번에 넣으면 구분이 안 되어 올릴 수 없습니다.)
- 보고서에서 로그를 고르지 않은 장비는 그 장비의 **가장 최근 로그**를 자동으로 씁니다.
- **perf_archive.7z** 도 같은 장비 칸에 넣으면 됩니다. 웹호스팅(PHP)은 7z 를 풀 수 없어서 **사용자 PC 브라우저 안에서** 7-Zip(WASM, `assets/vendor/7z/`)으로 풀어 분석하고, 원본은 조각으로 나눠 서버에 보관합니다. Chrome/Edge 최신 버전을 쓰세요.
- 원본 아카이브는 **90일 뒤 자동 삭제**됩니다(접속할 때 6시간에 한 번 정리, 크론 불필요). 분석 결과는 남습니다. 결과 창에서 **[보관 90일 연장]**, **[계속 보관]** 을 고를 수 있습니다.
- 장비에 최근 120일 안의 성능 분석이 있으면 **특별점검 보고서**에 **성능 세부 분석** 페이지가 들어갑니다. 정기점검 보고서에는 넣지 않습니다. (보고서 생성 3단계 또는 [정보 수정]에서 끌 수 있음)
- 장비 등록/수정의 **보고서에서 뺄 SVM·볼륨** 칸에 `svm01` 처럼 적으면 그 SVM 볼륨은 보고서에서 빠집니다. (`svm01:vol_tmp*` 처럼 볼륨만도 가능. SVM 루트·vol0 는 자동 제외)

## 5-3. cDOT 점검 명령어
- 화면의 **[📋 점검 명령어]** 에서 명령어를 복사해 장비에서 실행하고, 출력 전체를 텍스트 파일로 저장해 장비 칸에 넣습니다.
- **정기점검 보고서**에는 평시 항목, **특별점검 보고서**에는 평시 + 상세 항목 결과표가 들어갑니다. (7-Mode 는 추후 반영)
- 로그에서 하드웨어·볼륨 이상이 보이면 **육안 점검** 해당 항목이 '비정상'으로 미리 표시됩니다(⚡ 로그 자동). 현장에서 확인 후 엔지니어가 최종 선택합니다.

- 정기·특별 명령어 끝에는 **시스템 사용률** 명령어(`sysstat -x`, `ifstat -a`, `network interface show`, `statistics show-periodic`)가 붙어 있습니다. 이 출력이 로그에 있으면 보고서에 **노드별 CPU·디스크 사용률**과 **인터페이스별 네트워크 사용률** 표가 정기·특별 모두 들어갑니다. (60% 이상 요주의, 80% 이상 위험)
- `network interface show` 출력이 들어 있는 로그를 처음 올리면 장비의 **관리 IP**(cluster_mgmt, 노드 mgmt)와 SP IP가 자동으로 저장됩니다. [장비 수정]의 '관리 IP' 칸에서 직접 고칠 수도 있습니다.

## 5-3-0. 무시 설정 (판정에서 빼기)
- 보고서 상세의 장비 진단 항목마다 **[무시]** 버튼이 있습니다. 고객이 쓰지 않는 포트, 시험용 볼륨처럼 판정에 넣을 필요가 없는 항목을 빼는 데 씁니다.
- 적용 범위는 **이 장비에만**(엔지니어) 또는 **모든 장비**(관리자)입니다. 숫자가 바뀌어도(예: 91% → 93%) 같은 항목으로 보고 계속 뺍니다.
- 한 번 설정하면 같은 장비의 이후 보고서, 다시 분석하는 과거 보고서, 대시보드 판정에 자동으로 반영됩니다. 위험/요주의 판정과 점수에서 빠지고, 보고서 화면의 '무시 설정 항목'에 따로 보입니다.
- 이미 만든 PPT·엑셀에는 [보고서 생성]을 다시 눌러야 반영됩니다. 목록과 해제는 [시스템 설정 › 무시 설정 항목]에서 합니다.

## 5-3-1. 서비스 코드별 보고서
보고서 생성 2단계의 **Service Code**에 따라 보고서 구성이 바뀝니다. 여러 개를 고르면 합쳐집니다. 코드를 안 고르면 PM과 같습니다.

| 코드 | 들어가는 내용 | 서비스 작업 내역 칸 |
|---|---|---|
| PM 정기 예방 점검 | 용량·진단, 사용률, 점검 항목, 육안 점검 | 없음 |
| Repair 장애 처리·부품 교체 | 용량·진단, 점검 항목, 육안 점검 | 장애 증상, 원인, 조치 내용, 교체 부품, 조치 후 상태 |
| Install 신규 설치·구성 | 용량·진단, 점검 항목, 육안 점검 | 설치 범위, 구성 내용, 구성 검증, 라이선스, 인수 사항 |
| Deinstall 철거·반출 | 육안 점검 | 철거 대상, 데이터 처리, 종료 절차, 반출·인수 |
| Upgrade OS·펌웨어 | 용량·진단, 사용률, 점검 항목, 육안 점검 | 버전 변경, 진행 방식, 사전/사후 점검, 서비스 영향 |
| Move 장비 이전 | 용량·진단, 점검 항목, 육안 점검 | 이전 위치, 종료·기동, 재연결, 이전 후 상태 |
| Reconfig 구성 변경 | 용량·진단, 사용률, 점검 항목 | 변경 내용, 변경 전→후, 사유, 변경 후 확인 |
| etc 기타 | 용량·진단 | 작업 내용, 결과 |

- 작업 내역은 보고서 상세 화면의 **🛠 서비스 작업 내역**에서 적습니다. 적은 칸만 보고서(PPT 표, 엑셀 '서비스 작업' 시트)에 들어갑니다.
- AI 진단 조언도 코드별 중점(예: Repair = 원인·재발 방지)과 적은 작업 내역을 함께 봅니다.
- 구성은 `api/inc/catalog.php` 의 `SERVICE_PROFILE` 에서 바꿀 수 있습니다.

## 5-4. 오프라인 수집함 (내부망 장비)
웹 서버(호스팅)는 고객사 내부망 장비에 직접 접속할 수 없으므로, 엔지니어 PC 브라우저에서 수집하고 나중에 올립니다. 별도 프로그램은 필요 없습니다.
1. **인터넷이 되는 곳에서 미리** MRS에 로그인합니다. 로그인할 때마다 담당 고객·장비·관리 IP·명령어가 이 PC에 자동으로 저장됩니다. ([내 PC에 MRS 설치]를 해 두면 바탕화면 아이콘으로 바로 열립니다.)
2. 고객사 내부망에서 MRS를 엽니다. 인터넷이 안 되면 자동으로 **오프라인 모드**(수집함만 보임)로 열립니다.
3. 고객·장비와 **정기점검/특별점검**을 고르면 관리 IP와 명령어가 나옵니다. [명령어 복사] → PuTTY 등으로 장비에 접속해 실행합니다.
4. 출력 전체를 붙여 넣거나, 저장한 로그 파일·perf_archive.7z 를 넣고 **[수집함에 담기]**. 자료는 **이 PC 브라우저에만** 보관됩니다.
5. 인터넷이 되는 곳에서 수집함을 열고 **[모두 올리기]**(또는 건별 [올리기]). 장비별 로그·성능 아카이브로 들어가고, 올린 건은 수집함에서 지워집니다. 로그 메모에 '오프라인 수집함 · 정기점검/특별점검'이 남습니다.
- **수집함 파일로 옮기기**: 수집함의 **[💾 파일로 내보내기]**는 수집 자료 전체를 .mrsbox 파일 한 개로 저장합니다. 다른 PC의 MRS 수집함에서 **[📂 파일 가져오기]** 후 [모두 올리기] 하면 됩니다. 같은 자료를 두 번 가져와도 한 번만 담깁니다. 백업용으로도 쓰세요.

### 5-4-1. MRS 오프라인 수집기 (인터넷이 한 번도 안 되는 PC)
- 온라인 MRS의 [오프라인 수집함] 위쪽 **[💻 오프라인 수집기 파일 받기]**를 누르면 `MRS_collector_아이디_날짜.html` 파일 한 개가 내려받아집니다. 화면·내 장비 목록·관리 IP·명령어가 모두 들어 있습니다.
- 이 파일을 USB 등으로 내부망 PC에 옮겨 **더블클릭**하면 Chrome/Edge에서 인터넷·서버 없이 수집함 화면이 열립니다. 수집한 자료는 그 PC 브라우저에 보관되어 파일을 닫았다 다시 열어도 남아 있습니다.
- 수집이 끝나면 **[💾 파일로 내보내기]** → .mrsbox 파일을 인터넷 되는 PC로 옮겨 MRS **[📂 파일 가져오기]** → **[모두 올리기]**.
- 수집기 파일에는 고객·장비 이름과 관리 IP가 들어 있으므로 회사 PC·USB에서만 쓰세요. 비밀번호는 들어 있지 않습니다. 장비가 새로 생기면 파일을 다시 받으세요.
- 브라우저 사이트 데이터를 지우면 올리지 않은 수집 자료도 지워집니다. 로그아웃하면 이 PC의 오프라인 로그인 정보도 지워지므로, 내부망에 가기 전에는 로그인된 상태로 두세요.

## 6. PC에 설치 (MRS 아이콘)
Chrome/Edge 에서 접속 후 상단 **[내 PC에 MRS 설치]** 를 누르면 바탕화면·시작 메뉴에 MRS 아이콘이 생깁니다.

## 7. 보안 메모
- `config.php`(DB 비밀번호·암호화 키)와 `data/`(로그·보고서 파일)는 `.htaccess` 로 외부 접근을 막습니다. 절대 Git 에 올리지 마세요.
- `config.php` 의 secret 을 바꾸면 저장된 SMTP 비밀번호·API 키를 다시 입력해야 합니다.
- 다시 설치하려면 `config.php` 를 지우고 `install.php` 를 다시 올립니다. (기존 `mrs_` 데이터는 유지됩니다.)

## 8. 백업
- DB: `mrs_` 테이블 (PMS 백업과 함께 덤프)
- 파일: `mrs/data/` 폴더 (업로드 로그, 성능 아카이브, 생성된 보고서, 고객 양식)
